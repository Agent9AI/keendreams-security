# KeenDreams Security v0.1.0

The initial tagged release packages the evidence-backed MCP memory server,
browser review interface, account-free local demonstration, and optional
Tenable Hexa workflow instructions.

## What you can use

- Nine MCP tools for evidence, proposed relationships, retrieval, graph queries,
  and history, with OAuth sign-in and client-scoped memory.
- Semantic vector and keyword retrieval with trust and validity filtering.
- Browser confirmation/rejection, audit-chain verification, and rollback.
- A local demonstration requiring no Cloudflare or Tenable account, with
  [a reproduced first decision](../start-here.md).
- [Secure Hexa connection instructions](../integrations/tenable.md), including
  environment-variable credential references and live tool discovery.

The core server requires no Tenable account or Tenable One license. Hosted use
requires your own Cloudflare infrastructure and identity configuration. Hexa's
licensing and API permissions apply to its optional integration.

## Verification

All 238 offline tests across 26 files, typechecking, and lint passed on
2026-10-10. The locked dependency installation reported zero vulnerabilities.
The first-run browser check used the real local interface and synthetic data:
one confirmation moved the pending/confirmed counts from 3/1 to 2/2, and the
verified audit chain grew from eight to nine entries.

Live Hexa authentication, discovery of 95 tools, and one bounded asset-summary
query passed. The deployed KeenDreams OAuth connection and the earlier live
Cloudflare storage/AI checks are documented in the
[verification record](../verification.md).

## Boundaries

- The complete live Hexa finding-to-memory, human-review, and recall sequence is
  still pending. The Exchange interoperability flag remains false.
- Origin Observatory is a separate example application; its planned integration
  is not bundled or claimed complete in this release.
- Semantic indexing is asynchronous. The audit log has no retention policy yet.
- Model proposals do not become trusted through similarity or model confidence.
  Browser review is the ordinary path; explicitly configured automation trust
  allowlists are a separate administrative exception.
- Updating repository code does not update an existing hosted deployment.
